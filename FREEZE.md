## What "frozen" means from here

The trained model artifact (`model/model.joblib`, gitignored, reproducible from this commit's code + cached data) is what Week 1 will actually be scored against. Legitimate, expected activity after this tag: re-running `run_week.py` to refresh injury data/inactives/lines closer to each kickoff (predictions ledger only grows, never overwrites), and running `grade.py` after games complete. Not expected: further changes to `model/train.py`'s features, `model/elo.py`'s constants, or anything else that would change what the frozen model actually learned.

## One honest caveat carried forward from today's work

Retraining twice today with identical code and cached data produced two different `model.joblib` byte-hashes (`868ceb0f3dd0` and, briefly, `c202b33b0019`) despite reporting identical headline metrics (0.668 accuracy, 0.2116 Brier) both times. The final, tagged state is `868ceb0f3dd0`. `model_version_hash()` guarantees a prediction is tied to one specific serialized artifact — it does not by itself prove two different hashes represent a meaningfully different model; that distinction wasn't tracked down further here (plausibly XGBoost's own non-deterministic multi-threaded training, not a real behavior change, since the metrics didn't move).

## Post-freeze serving fixes (2026-09-21, after Week 2's Sunday games)

The model is still frozen: `model/model.joblib` is byte-identical (`868ceb0f3dd0`), the features, training data and training code are untouched, and no logged Week 1–2 prediction was edited. What changed is everything around it that only Week 2+ exercises -- Week 1 scores entirely off the prior-season fallback, so none of this could show up until a week with real 2026 results:

- **Team stats were wrong for every week after Week 1.** `model/predict.py::_current_season_stats` kept rolling rows with `week < W`, but those rows are already pre-game, so Week 2 got an all-NaN Week 1 row and Week 3+ got stats one game stale. Now `data/live_stats.py` takes each team's first row at/after W (prior season included, so `ats_win_pct_last5` crosses the season boundary as in training). `qa/validate_live_stats.py` proves live stats reproduce the cached training rows exactly (weeks 2 and 9 of 2025, max difference 0); it is a hard-fail step in `weekly_pipeline.sh`.
- **NaN model inputs.** After one game some stats are undefined (no red-zone trips, only pushes ATS); the model never trained on a NaN. They are now filled from the team's prior-season value (`fill_missing_stat_values`). Three logged Week 2 games were scored with one such NaN -- see `logs/ledger_annotations.jsonl`.
- **Elo hindsight.** `get_current_elo_ratings` replayed every played game, so a game already played this week was "predicted" from ratings containing its own result. It is now as-of the start of the week.
- **Logging after kickoff.** `run_week.py` logged every game it scored, including ones already played (results CSV, props CSV, ledger). Started games are now skipped, and rows already logged for them are kept.
- **Reports were a run behind.** The report was built before grading, so Track Record/archive/recap always lagged one run. Grading and logging now come first. Played games show the final score and whether the pre-game pick was right (from the ledger); a game with no pre-game pick on record says so instead of showing a hindsight number.
- **pandas 3 grading crash** on the first pending row (`Invalid value 'SEA' for dtype 'float64'`), and **Odds API failure** (dead key) now falls back to nflverse lines, tagged `market_lines_source`, without the key ever appearing in an error message.
- **`pbp_participation_<season>` missing** early in a season (nfl_data_py's own handler for it is broken) no longer kills current-season pbp loads.
- **Weekly retraining changed the model hash for nothing.** `HISTORICAL_SEASONS` is completed seasons only, so the weekly retrain refit identical data -- but `model.calibration` re-serializes `model.joblib` unconditionally and XGBoost training is not byte-reproducible (a scratch retrain today matched on model type, features and holdout but differed by one game out of 271), so the hash on every logged prediction changed weekly. `model/train_guard.py` now retrains only when the training inputs' fingerprint changes and archives the deployed model to `model/archive/model_<hash>.joblib` first. Baseline recorded 2026-09-21.
- **Tests** are now offline-enforced (`tests/conftest.py`); the HTML-escaping test that needed DNS had failed the whole pipeline (`set -e`) on Sep 16.

Team hubs (record, EPA trend) previously read caches that end at last season; they now include this season's results so far.

### Second pass -- found by an independent review of the above, fixed the same day

- **Blowout-loss flag was 0 for every upcoming game.** `data/situational.py` built its margin table from completed games only, so live scoring never found a row for a game not yet played and `blowout_loss_diff` silently defaulted to 0 (a team that lost 10-40 in Week 1 should have flagged in Week 2). It now has a row for every scheduled game. All 5,278 historical rows are byte-for-byte identical before and after, so the frozen model's training inputs did not change.
- **Undefined home/away point-diff splits** were left NaN (-> 0.0 home-field context) live, while training fills them from the prior season like every other stat. They are now filled the same way.
- **Data completeness guards.** Pre-game stats now refuse to build if the schedule shows a game as played that the play-by-play doesn't contain, or if any team is missing from the selection, and the "undefined stats" guard checks the play-by-play-derived columns (the schedule-derived ones could never trip it).
- **Logging.** A re-run now replaces only the rows it is re-logging -- it used to drop a valid pre-kickoff row for any game it produced no new prediction for, and wiped the whole props log when the Odds API was down. A game with a final score counts as started even with no kickoff time. Grading failures can no longer block logging new picks; CSV writes are atomic. `grade.py` skips any ledger record written after its game's kickoff.
- **Secrets.** Network errors (not just HTTP-status errors) from the Odds API could print the key; they no longer can. `qa/scan_secrets.py` (dotenv-parsed, so quoting/`export`/comments/CRLF all resolve) checks the artifact and every log before `publish_pages.sh` pushes anything.
- **Reliability.** Every nfl_data_py download now retries transient failures (`data/nfl_net.py`; a 404 still fails fast), the historical fetch keeps its existing cache rather than failing the run, and the informational QA steps can no longer abort the pipeline. All three were hit within a single morning of flaky DNS/504s.
- The retrain fingerprint now also covers `data/fetch_injuries.py`, `data/baselines.py` and `data/positional_matchups.py` (unchanged since before the model was trained; baseline re-recorded).
